# Trade Router 구현 상태와 다음 순서

기준일: 2026-10-23

이 문서는 [최종 설계](ARCHITECTURE.md)와 실제 코드 사이의 차이를 기록한다.
완료 표시는 자동 테스트와 공통 SDK 경로가 모두 있는 기능에만 붙인다.

## 현재 사용할 수 있는 범위

v0.1.74에서 조건식 없이 명시적인 매도 주문만 있는 계층을 지원한다. 작동 시간·매도 대상·출처 잔량·미체결 보호를 그대로 적용하며, 하위 계층의 주문은 상위 조건을 통과해야 한다. 마지막 조건을 삭제해도 명시적인 매도 주문은 남고, 주문이 없는 빈 구성은 실행하지 않는다. 조건 없는 매도는 설정한 매도 확인 간격으로 평가한다.

전략 종료의 안전한 요약(종료 코드·사용자 중지 여부·허용된 예외 종류·Windows 오류 번호)을 DB에 보존하고, 앱 재시작 후에도 별도 최근 종료 이력으로 진단 자료에 포함한다. 종료 정리 문구를 실시간 구독 오류로 분류하던 문제와 이전 종료 정리 중 재실행하는 경쟁을 수정했다. Windows 파일 교체가 일부 진행된 뒤 실패하는 경우에도 확정된 본 파일·복구 기록의 백업을 남기고 재시작 시 최신 버전을 복구한다.

v0.1.73에서 Windows 상태 파일 읽기·교체 경합을 수정했다. 대시보드의 읽기는 파일 교체를 허용하는 공유 모드를 사용하고, 기존 파일은 `ReplaceFileW`로 교체한다. 외부 파일 잠금이 남아 있으면 최신 상태를 디스크의 복구 기록에 먼저 저장한 뒤 별도 작업에서 반영을 재시도한다. 상태 버전 번호로 이전 기록이 최신 값을 덮어쓰지 못하게 하며, 종료 후에도 반영하지 못한 기록은 다음 실행에서 복구한다. 디스크 쓰기 자체가 실패한 경우는 조용히 무시하지 않는다.

v0.1.71에서 관리형 블록의 매수 조회, 봉 매도, 실시간 수익률 매도, 체결 처리를 독립 실행한다. 일반 Python 전략은 기존 직렬 실행을 유지한다. 실시간 손절은 매수 검색·봉 계산을 기다리지 않으며, 봉 조건과 AND로 묶인 경우 같은 판단 기간에 확보한 봉 자료가 있어야 통과한다. 자료가 없거나 오래됐으면 그 AND 경로를 보류하고, 독립적인 OR 수익률 경로는 계속 평가한다. 주문 허용·잔량·시장 시간·가격 유효성 검사는 그대로 적용하며, 신호 판단과 증권사 체결 완료는 별개다.

봉 자료 준비는 독립된 매도 경로에서 5초마다 필요 여부를 확인하고, 완성봉은 해당 봉 주기 안에서 재사용한다. 앞의 수익률 조건이 아직 거짓이어도 AND로 연결된 봉 조건을 준비한다. KIS의 요청 입구는 주문, 계좌·현재가, 종목검색·봉 조회 순으로 대기 우선순위를 적용하며 낮은 우선순위도 무한 대기시키지 않는다. 이미 송신한 HTTP 요청 한 건의 완료·시간 초과와 주문 전 1.1초 보호 간격은 유지한다. 따라서 손절 가격 도달과 같은 가격의 즉시 체결을 보장하지는 않는다.

새 매도 구성의 대상은 여러 매수 흐름 전체와 내부 IF·중첩 조건을 함께 선택할 수 있다. 매수 주문에 실제 통과한 흐름·조건 ID를 기록하고 실제 체결 수량만 출처 원장에 반영한다. 겹친 선택은 합집합이며, 주문 중앙부에서 출처 잔량을 초과하는 매도를 차단한다. 선택하지 않은 연결 매도는 대기한다. 과거 출처 없는 보유분은 임의로 연결하지 않으므로 필요하면 명시적인 보유 범위 모드를 사용한다. v0.1.72부터 대상 방식은 매수 연결과 보유 범위만 사용하며, 모든 매도 규칙에 별도의 `operating_start_time`·`operating_end_time`을 둔다. 실시간 시세, 봉 판단, 보완 조회와 봉 사전조회가 한국시간 시작 포함·종료 제외의 같은 작동 시간과 주말 제외 기준을 사용한다. 조회가 늦어진 경우 주문 요청 직전에 현재 시각을 다시 확인한다. 기존 시간 방식은 보유 범위로 전환하고 초 단위 시작·종료 시각을 그대로 옮긴다. 기존 매수 연결·보유 범위 방식은 종전 주기 감시 범위인 08:00~20:00으로 옮기며, 대상·조건·주문·출처 연결은 유지한다. 작동 시간 종료는 이미 제출한 주문의 자동 취소나 보유종목 강제 청산을 뜻하지 않는다. 전략 예산·보유 원장·중복 미체결 차단은 공유한다.

관리형 블록 전략은 별도 계산 노드 없이 비교 조건의 좌우 값에 계산 설정을 포함한다. 좌우 값은 서로 다른 1~120분봉 또는 일봉, 완성봉·진행 중 봉, N봉 전 값, 일반 OHLC·하이킨아시 OHLC, 볼린저 기간·표준편차, OBV와 ATR을 사용할 수 있다. ATR은 이전 종가를 포함한 원본 OHLC의 True Range를 초기 평균 뒤 Wilder 방식으로 평활하고 최대 100봉의 고정 워밍업을 적용해 차트와 실행기의 값이 일치한다. 좌우 값은 숫자·지표와 `+ - × ÷`만으로 구성한 타입 수식으로 감쌀 수 있으며, 임의 코드 실행 없이 깊이·항목 수·유한값·0 나눗셈을 검증한다. 완성봉 화면의 1봉 전은 내부 offset 0인 가장 최근 완성봉이다. OBV의 임의 기준점이 조건을 바꾸지 않도록 같은 봉 주기·봉 상태의 두 OBV 시점만 직접 비교한다. 상향·하향돌파는 모든 봉 지표가 같은 봉 주기·봉 상태인 수식에만 허용하고 실시간 수익률에는 허용하지 않는다. 조건 블록 내부 비교식은 위에서부터 확인하는 OR이고 여러 조건 블록은 순차 AND다. 실행기는 실제로 도달한 비교식이 참조하는 봉만 준비하며 OR이 충족되거나 앞 블록이 실패하면 뒤 비교식·블록 자료는 조회하지 않는다. 이미 받은 같은 종목·봉 주기·봉 상태의 자료는 필요한 수량이 충분하면 재사용한다. 봉을 쓰지 않는 조건만 있으면 어댑터에 과거 봉 기능을 요구하지 않는다. 하이킨아시 비교는 24개 원본 봉으로 재귀 시가를 준비한다. 단일 요청 400봉을 넘는 지표 이력은 이전 봉을 순차 조회하고, 증권사·봉 주기별 전체 조회 가능 범위를 넘는 설정은 저장 전에 거절한다. 완성 일봉은 KRX 15:30, NXT·통합 20:00 이후 당일 봉을 포함한다. 매수는 설정된 판단 시작 시각에 판단하고, 매도는 작동 시간 안에서 설정한 확인 간격으로 판단하며 같은 기간의 자료를 재사용한다. 진행 중 봉은 설정한 조회 주기로 매수·매도 조건을 다시 계산한다. KIS 공통 Python SDK의 주봉 조회도 별도로 지원한다.

관리형 블록은 종목 수집과 거래 시장을 분리한다. HTS 조건검색·순위·지정 종목으로
후보를 만든 뒤 `market_venue`(KRX·NXT·INTEGRATED)의 현재가와 봉으로 조건을
판단하고, 별도의 `route`(KRX·NXT·SOR·AUTO)로 주문한다. HTS 조건검색 응답 자체는
거래 시장별 목록이 아니며, NXT 주문 가능 여부는 계좌 기능표와 주문 전 조회에서
검증한다. KIS 모의 연결의 NXT 주문은 외부 주문 요청 전에 차단한다.

각 매수·매도 행동은 최유리지정가(`BEST_LIMIT`)를 선택할 수 있다. KIS의 일반
최유리지정가 코드 `03`으로 가격 `0`을 전송하며, 주문 가능 수량 조회도 같은
주문 유형과 증권사가 반환한 계산단가를 사용한다. NXT 프리(08:00~08:50),
메인(09:00:30~15:20), 애프터(15:40~20:00) 접속매매에서 실행하며,
15:30~15:40 단일가 구간에는 주문을 보류하고 이후 조건을 다시 판단한다.
미체결·부분체결은 기존 중복 방지와 주문 조정을 유지하며 가격을 자동 추격하지
않는다. NAMUH의 최유리지정가는 지원하지 않아 명시적으로 거절한다.

블록의 시간대별 매수 흐름은 적용 시간·조회 주기·종목 데이터 설정·매수 조건 블록을
독립적으로 보관한다. 여러 흐름은 한 전략의 계좌·예산·보유종목·주문 방식을 공유하고
매도 조건·청산 일정도 공통으로 유지한다. 시간 구간은 한국 시각의 시작 포함·종료
제외이며 조회나 조건 계산이 늦어지면 주문 요청 전에 흐름의 유효 시간을 재검사한다.
이전 형식의 단일 종목 데이터·매수 일정·매수 조건 설정은 한 흐름으로 호환한다.
편집 화면은 시간대별 그룹 아래 조회·조건·주문을 중첩하는 세로 일정 형태이며,
공통 설정과 세부 조건을 접고 펼친다. 실행 방식은 검증한 설정으로 Python
스크립트를 생성하는 기존 관리형 컴파일러를 유지한다.

## 다음 구현 순서

1. **데이터와 거래일**
   - 종목 마스터·이름 검색·ETF/ETN 분류 캐시
   - 한국 거래소 휴장일 달력과 장 상태
   - 장기간 실행을 위한 날짜 전환, 연결 건강 상태와 자동 복구 시험

2. **증권사 확장**
   - NAMUH 과거 봉과 종목 마스터를 공통 모델로 추가
   - KIS·NAMUH 읽기 전용 실계정 연동 시험과 모의 주문 수동 검증
   - 공통 기능과 `provider_options` 확장 기능을 분리한 계약 테스트

3. **전략 개발 도구**
   - 과거 데이터 재생과 주문 없는 시뮬레이션
   - 전략별 주문·체결·손익 타임라인과 내보내기
   - 업데이트 실패 시 이전 프로그램 파일로 되돌리는 자동 롤백

KIS·NAMUH 경로는 WebSocket 단절 중에도 REST 주문 조정이 계속되며 재연결 뒤 원하는
구독을 다시 등록한다. 실제 계좌 수수료 계약은 사용자마다 다르므로 계좌 설정값을
사용하고, 비어 있을 때 임의 요율을 적용하지 않는다.
