관리형 블록 전략은 별도 계산 노드 없이 비교 조건의 좌우 값에 계산 설정을 포함한다. 좌우 값은 서로 다른 1~120분봉 또는 일봉, 완성봉·진행 중 봉, N봉 전 값, 일반 OHLC·하이킨아시 OHLC, 볼린저 기간·표준편차, OBV와 ATR을 사용할 수 있다. ATR은 이전 종가를 포함한 원본 OHLC의 True Range를 초기 평균 뒤 Wilder 방식으로 평활하고 최대 100봉의 고정 워밍업을 적용해 차트와 실행기의 값이 일치한다. 좌우 값은 숫자·지표와 `+ - × ÷`만으로 구성한 타입 수식으로 감쌀 수 있으며, 임의 코드 실행 없이 깊이·항목 수·유한값·0 나눗셈을 검증한다. 완성봉 화면의 1봉 전은 내부 offset 0인 가장 최근 완성봉이다. OBV의 임의 기준점이 조건을 바꾸지 않도록 같은 봉 주기·봉 상태의 두 OBV 시점만 직접 비교한다. 상향·하향돌파는 모든 봉 지표가 같은 봉 주기·봉 상태인 수식에만 허용하고 실시간 수익률에는 허용하지 않는다. 조건 블록 내부 비교식은 위에서부터 확인하는 OR이고 여러 조건 블록은 순차 AND다. 실행기는 실제로 도달한 비교식이 참조하는 봉만 준비하며 OR이 충족되거나 앞 블록이 실패하면 뒤 비교식·블록 자료는 조회하지 않는다. 이미 받은 같은 종목·봉 주기·봉 상태의 자료는 필요한 수량이 충분하면 재사용한다. 봉을 쓰지 않는 조건만 있으면 어댑터에 과거 봉 기능을 요구하지 않는다. 하이킨아시 비교는 24개 원본 봉으로 재귀 시가를 준비한다. 단일 요청 400봉을 넘는 지표 이력은 이전 봉을 순차 조회하고, 증권사·봉 주기별 전체 조회 가능 범위를 넘는 설정은 저장 전에 거절한다. 완성 일봉은 KRX 15:30, NXT·통합 20:00 이후 당일 봉을 포함하고 다음 실행일의 설정된 판단 시작 시각에 한 번 판단한다. 진행 중 봉은 설정한 조회 주기로 매수·매도 조건을 다시 계산한다. KIS 공통 Python SDK의 주봉 조회도 별도로 지원한다.

관리형 블록은 종목 수집과 거래 시장을 분리한다. HTS 조건검색·순위·지정 종목으로
후보를 만든 뒤 `market_venue`(KRX·NXT·INTEGRATED)의 현재가와 봉으로 조건을
판단하고, 별도의 `route`(KRX·NXT·SOR·AUTO)로 주문한다. HTS 조건검색 응답 자체는
거래 시장별 목록이 아니며, NXT 주문 가능 여부는 계좌 기능표와 주문 전 조회에서
검증한다. KIS 모의 연결의 NXT 주문은 외부 주문 요청 전에 차단한다.

각 매수·매도 행동은 최유리지정가(`BEST_LIMIT`)를 선택할 수 있다. KIS의 일반
최유리지정가 코드 `03`으로 가격 `0`을 전송하며, 주문 가능 수량 조회도 같은
주문 유형과 증권사가 반환한 계산단가를 사용한다. NXT 프리(08:00~08:50),
메인(09:00:30~15:20), 애프터(15:40~20:00) 접속매매에서 실행하며,
15:30~15:40 단일가 구간에는 주문을 보류하고 이후 조건을 다시 판단한다.
미체결·부분체결은 기존 중복 방지와 주문 조정을 유지하며 가격을 자동 추격하지
않는다. NAMUH의 최유리지정가는 지원하지 않아 명시적으로 거절한다.

블록의 시간대별 매수 흐름은 적용 시간·조회 주기·종목 데이터 설정·매수 조건 블록을
독립적으로 보관한다. 여러 흐름은 한 전략의 계좌·예산·보유종목·주문 방식을 공유하고
매도 조건·청산 일정도 공통으로 유지한다. 시간 구간은 한국 시각의 시작 포함·종료
제외이며 조회나 조건 계산이 늦어지면 주문 요청 전에 흐름의 유효 시간을 재검사한다.
이전 형식의 단일 종목 데이터·매수 일정·매수 조건 설정은 한 흐름으로 호환한다.
편집 화면은 시간대별 그룹 아래 조회·조건·주문을 중첩하는 세로 일정 형태이며,
공통 설정과 세부 조건을 접고 펼친다. 실행 방식은 검증한 설정으로 Python
스크립트를 생성하는 기존 관리형 컴파일러를 유지한다.

## 다음 구현 순서

1. **데이터와 거래일**
   - 종목 마스터·이름 검색·ETF/ETN 분류 캐시
   - 한국 거래소 휴장일 달력과 장 상태
   - 장기간 실행을 위한 날짜 전환, 연결 건강 상태와 자동 복구 시험

2. **증권사 확장**
   - NAMUH 과거 봉과 종목 마스터를 공통 모델로 추가
   - KIS·NAMUH 읽기 전용 실계정 연동 시험과 모의 주문 수동 검증
   - 공통 기능과 `provider_options` 확장 기능을 분리한 계약 테스트

3. **전략 개발 도구**
   - 과거 데이터 재생과 주문 없는 시뮬레이션
   - 전략별 주문·체결·손익 타임라인과 내보내기
   - 업데이트 실패 시 이전 프로그램 파일로 되돌리는 자동 롤백

KIS·NAMUH 경로는 WebSocket 단절 중에도 REST 주문 조정이 계속되며 재연결 뒤 원하는
구독을 다시 등록한다. 실제 계좌 수수료 계약은 사용자마다 다르므로 계좌 설정값을
사용하고, 비어 있을 때 임의 요율을 적용하지 않는다.
