# Trade Router 구현 상태와 다음 순서

기준일: 2026-10-15

이 문서는 [최종 설계](ARCHITECTURE.md)와 실제 코드 사이의 차이를 기록한다.
완료 표시는 자동 테스트와 공통 SDK 경로가 모두 있는 기능에만 붙인다.

|---|---|---|

| 인증·호출 한도 | 완료 | KIS·NAMUH 토큰 공유, 연결별 큐, 우선순위, 중복 조회·캐시 |

| KIS 계좌·주문 | 완료 | 잔고, 주문 가능 수량, 당일 주문·체결, KRX·NXT·SOR 현금 시장가·지정가 |

| NAMUH | 대부분 완료 | 실전·모의 인증, 현재가, 잔고, 주문 가능 수량, 당일 주문, 현금 주문·정정·취소; 과거 봉 제외 |

| 수정·취소 주문 | 완료 | KIS·NAMUH 미체결 사전조회, 공통 SDK, 불명확 응답 조정 |
| 거래 비용 손익 | 완료 | 체결별 수수료·세금 원장과 비용 반영 손익; 계좌별 요율 미설정 시 미확정 표시 |

관리형 블록 전략은 OHLCV·볼린저 계산 노드와 비교 조건 노드를 분리한다. 조건 블록 내부 비교식은 OR, 여러 조건 블록은 AND이며 각 블록마다 1~120분봉 또는 일봉과 완성봉·진행 중 봉을 독립 선택한다. 같은 종목·봉 주기·봉 상태를 쓰는 계산은 한 번의 봉 조회로 합친다. 봉 주기·지표 기간·N봉 전 값에 필요한 이력이 1회 조회 범위를 넘으면 저장 전에 거절한다. 완성 일봉은 KRX 15:30, NXT·통합 20:00 이후 당일 봉을 포함하고 다음 실행일의 설정된 판단 시작 시각에 한 번 판단한다. 진행 중 봉은 설정한 조회 주기로 매수·매도 조건을 다시 계산한다. KIS 공통 Python SDK의 주봉 조회도 별도로 지원한다.

관리형 블록은 종목 수집과 거래 시장을 분리한다. HTS 조건검색·순위·지정 종목으로
후보를 만든 뒤 `market_venue`(KRX·NXT·INTEGRATED)의 현재가와 봉으로 조건을
판단하고, 별도의 `route`(KRX·NXT·SOR·AUTO)로 주문한다. HTS 조건검색 응답 자체는
거래 시장별 목록이 아니며, NXT 주문 가능 여부는 계좌 기능표와 주문 전 조회에서
검증한다. KIS 모의 연결의 NXT 주문은 외부 주문 요청 전에 차단한다.

## 다음 구현 순서

1. **데이터와 거래일**
   - 종목 마스터·이름 검색·ETF/ETN 분류 캐시
   - 한국 거래소 휴장일 달력과 장 상태
   - 장기간 실행을 위한 날짜 전환, 연결 건강 상태와 자동 복구 시험

2. **증권사 확장**
   - NAMUH 과거 봉과 종목 마스터를 공통 모델로 추가
   - KIS·NAMUH 읽기 전용 실계정 연동 시험과 모의 주문 수동 검증
   - 공통 기능과 `provider_options` 확장 기능을 분리한 계약 테스트

3. **전략 개발 도구**
   - 과거 데이터 재생과 주문 없는 시뮬레이션
   - 전략별 주문·체결·손익 타임라인과 내보내기
   - 업데이트 실패 시 이전 프로그램 파일로 되돌리는 자동 롤백

KIS·NAMUH 경로는 WebSocket 단절 중에도 REST 주문 조정이 계속되며 재연결 뒤 원하는
구독을 다시 등록한다. 실제 계좌 수수료 계약은 사용자마다 다르므로 계좌 설정값을
사용하고, 비어 있을 때 임의 요율을 적용하지 않는다.
